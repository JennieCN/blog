这是「融夕的书」的第一篇文章，记录整个站点的架构选型、演进过程与日常运维习惯。

## 初版架构与演进（2026-11 更新）

站点最初采用前后端分离的双层结构起步，并在 2026 年 11 月中旬统一收拢到单台主力服务器的容器编排栈中，兼顾长文排版、大体积测评归档与自动备份：

- **初版方案（2026-11-09）**：内容主站基于 Astro 5 构建静态页面托管于 Cloudflare Pages，问答社区运行在独立云实例上的 Flarum。
- **现行线上架构（2026-11-18 起）**：主站（`blog.mycampusmail.com`）与问答社区（`qa.mycampusmail.com`）统一运行在同一套 Docker Compose 编排栈下，由 **Caddy** 负责自动证书续期与反向代理，博客采用 **Halo 2.27** 承载长篇技术笔记与可交互测评归档，社区继续由 **Flarum** 提供注册发帖与问答互动，配合每日凌晨定时落盘快照备份；同时本地 Git 仓库保留完整 Markdown 源码与自动化发布校验脚本。

### 为什么坚持博客与问答双站并行

长篇博客适合沉淀结构化笔记、分类索引与原始测试数据；而注册制问答社区适合围绕具体配置报错、车队调参或选机疑问做多轮讨论。把两者通过顶部导航栏与分类入口打通，既保住了正文阅读的清爽度，又保留了完整的社区交流空间。

## 常用服务器巡检命令

日常排查 VPS 资源与网络状态时最常用的命令如下（可点击右上角一键复制）：

```bash
# 查看 CPU、内存、Swap 与磁盘占用
nproc && free -m && df -h /

# 查看监听中的 TCP/UDP 端口
ss -lntup
```
